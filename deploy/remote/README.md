## Services and network

Review/install the `.service` and `.timer` templates on Linux. They are not installed by this kit. Controller execution is supervised independently of SSH/viewer connections. The current controller consumes mode-0600 operator requests from its private spool and supports only the existing read-only LangGraph/Codex executor. It is not yet connected to the existing viewer or a remote HTTP admission API. A request has exactly `request_key`, `conversation_id`, `project_id`, `question`. Duplicate keys cannot change a question or start another task. Final results are private SQLite records. Admission is durable before a request is renamed as accepted. Malformed, oversized, symlinked or non-private files are renamed as rejected without logging their contents or restarting other tasks. The operator may inspect and remove those private files; the controller never silently edits and replays them.

Worker RPC requires mutually authenticated TLS and body signatures, timestamps and durable nonce replay checks. Generate certificates privately with separate controller and worker identities and test hostname/CA validation. Defaults bind worker RPC to loopback; for a two-machine private-network deployment, explicitly bind its private address and firewall port 7443 to the controller's private address only. Never publish WebDriver, VNC, Docker, metadata access or the local JARVIS viewer publicly. Do not change the viewer's bind address. SSH forwarding can support operator viewing; execution must survive its loss.

The worker needs trusted access to Docker and systemd to create hard-expiry timers. Its root service is a deliberately narrow trusted boundary; browser containers/agents receive none of that access. Verify the read-only container's writable runtime paths on the actual image before accepting readiness. A reaper timer runs independently every 15 seconds, and per-workspace systemd timers enforce container expiry. External navigation stays unavailable until network isolation is independently implemented and tested. The current Watch API returns only the controlled session's screenshot on demand, with no VNC/input endpoint. Viewer authentication/cookies/CSRF/CSP/SSE and live streaming are not yet integrated.

## Backup, restore, rollback and teardown

Stop/quiesce the relevant service before taking operator-selected state snapshots. `tools/backup_execution.py backup NEW_PRIVATE_DIR DB.sqlite ...` uses SQLite's backup API, integrity checks and SHA-256 manifests. It does not copy configuration, notes or auth. `restore NEW_PRIVATE_DIR BACKUP_DIR` verifies hashes and writes a fresh directory. Private configuration/selected notes require a separately authorized backup policy. A local fixture restore is not a successful remote application restore. Never overwrite a live database. Map restored store names back to their configured paths only while stopped, preserving permissions; original filenames are recorded after the numeric disambiguation prefix.

Rollback: disable affected flags, Stop/fence active execution, confirm process/container settlement, retain uncertain operations and journals, select the prior code/dependency revision, restore verified state if required, and run full checks. Do not replay pending writes or resume a Deep Agents run; that capability is unsupported. Running tasks retain their initial behavior bundle.

Teardown: stop admission/controller, request workspace destruction, run the reaper, inspect both container and network inventories, verify no labelled resources remain, stop/remove only JARVIS-owned expiry units and services, retain or erase private state according to consent, and remove only explicitly selected provider instances/disks after reviewing the console. Nothing here purchases or deletes cloud resources automatically. Cleanup failures remain pending.
